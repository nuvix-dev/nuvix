The platform app is the control plane: project lifecycle + background
tenant-PostgreSQL provisioning (D20) and per-project configuration surfaces
(keys, platforms, auth settings, OAuth2/SMTP, templates, metadata,
database introspection, webhooks). All routes are console-operator-facing.

## Auth posture

**Console JWT (implemented).** Every route requires
`Authorization: Bearer <accessToken>` — a short-lived console JWT
(`aud: 'console'`, 15 min default) issued by `POST /console/auth`.
Public exceptions: `GET /health` and the `/console/auth*` endpoints.
Missing/invalid/expired → `401 console_unauthorized`. See
`docs/api/console.md` for the token model (rotating refresh tokens, reuse
detection, env-seeded bootstrap operator) and the
`/console/auth`, `/console/auth/refresh`, `/console/auth/logout`,
`/console/me` endpoints.

## Prefix (D39)

No `/v2` prefix — D26 scopes that to the project-facing server. The platform
app is versioned independently, runs on its own port (`config.platform.port`),
and starts unprefixed at the root until a second platform API version exists.

### Project object

```json
{
  "$id": "proj_abc123",
  "name": "My Project",
  "status": "active",
  "publishableKey": "pk_0195f87e323b7ca2813bb8a274a7b7ca",
  "containerName": "nuvix-tenant-proj_abc123",
  "volumeName": "nuvix-tenant-proj_abc123-data",
  "description": null,
  "logo": null,
  "url": null,
  "$createdAt": "2026-09-14T10:00:00.000Z",
  "$updatedAt": "2026-09-14T10:00:05.000Z"
}
```

- `status` ∈ `provisioning | active | error`. `errorMessage` is present only
  when `status: "error"`.
- `publishableKey` is generated by the platform, uniquely selects this project
  on the project-facing API, and is intentionally public. It never authorizes a
  request; tenant-local credentials are evaluated only after project selection.
- The tenant's connection coordinates (`target`: host/port/user/password) are
  **never returned** — stored encrypted at rest (D37) and used only
  server-side to resolve a project's tenant connection. Same never-returned
  posture as `teams.md`'s membership `secret`.
- `containerName`/`volumeName` are not secrets (no credentials) and are
  returned for operator debugging.

### `POST /projects`

Body: `{ name, id?, description?, logo?, url? }`. `id` follows the standard
ID convention (D28) — `'unique()'` (default) or a caller-supplied id.

Provisioning is **two-phase** (background): `POST /projects` reserves the
tenant container (fast, inline) and returns the project with
`status: "provisioning"` immediately; the slow tail — readiness wait +
`auth`-schema bootstrap — runs on the PROJECTS queue (`apps/platform/src/
workers/projects.processor.ts`, 3 attempts / exponential backoff) and flips
the record to `active` (or `error` + `errorMessage` on final failure).
Without Redis the app degrades to inline provisioning (same synchronous
behavior as before). `GET /projects` / `GET /projects/:id` poll status.

### `DELETE /projects/:id`

Query: `?purge=true` (default `false`). Without `purge`, the tenant container
is removed but its data volume is kept (D37's "keep by default" rule) —
there is no separate undelete endpoint yet, so the volume is the only
recovery path if a deletion was a mistake. `purge=true` also destroys the
volume. Returns `204`.

### Project JWTs

`POST /projects/:projectId/jwts` body `{ scopes: string[] (≤100),
duration: 0–3600 }` → `{ jwt }` (`400 jwt_disabled` when no JWT secret is
configured). These are the console-issued project tokens consumed by the
server's admin surfaces (e.g. `GET /v2/logs`).
